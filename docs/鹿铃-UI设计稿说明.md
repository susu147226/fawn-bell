## 二、每张稿子看什么

### 01 主界面（浅色 · 网格）
- **三栏骨架**：左 240px（目录树 / 分组 / 智能集合 / 保护区）· 中（面包屑 + 工具栏 + 类型页签 + 筛选 + 素材网格）· 右（预览 + 字段 + 待提交变更）。工具栏的视图切换为**四档**（文件夹 / 网格 / 列表 / 详情），本稿停在**网格**视图（文件夹视图见 07 / 08）。
- **三态视觉编码**（对应 7.2）：真实未动 = 无标记；**草稿态 = 缩略图左上橙色圆点 + 卡片橙边 + 「草稿」琥珀徽标**；**已整理 = 绿色 ✓ 徽标**；**受保护 = 右上灰色锁标**。
- **多选**：选中卡片显示蓝色核对勾；底部状态条常驻「已选 12 项 · 待提交 12 项变更（1 项有问题）· 保护区 210」。
- 右栏「待提交变更」卡片用 `原文件名 → 新文件名` 的 diff 呈现单条变更，并给出「撤销此项 / 查看冲突」两个就地操作——**右侧不做执行按钮**，执行只发生在 04 的变更集里。

### 02 主界面（深色 · 列表）
- 深色主题为**同等公民**：语义色（草稿琥珀 / 已整理绿 / 冲突红 / 锁定灰）在深色下重新取值，不是简单反色。工具栏与 01 同为四档视图，本稿停在**列表**视图。
- 列表视图用「类型」列表达素材类型（JPEG / PNG / MP4 视频 / BLEND），因此**不在 34×24 的小色块上叠角标**。
- 右栏换成**变更集摘要**：27 项待提交、涉及素材 24、分类计数（改名 18 / 移动归档 6 / 分组 3 / 受保护区跳过 210 / 冲突 1）、批量操作（全部提交 / 全部放弃）、变更类型分布条。
- 冲突行整行红底 + 「冲突：目标已存在」，草稿行整行琥珀底——**颜色之外还有文字**，满足执行版 **8.2 视觉设计规范**中「不做仅靠颜色的信息传达」一条。

### 03 批量重命名
- 左栏四组规则：① 命名模板（模板输入框 + **预设芯片区** + 变量芯片 + 「工程安全命名」小按钮）② 序号规则 ③ 冲突处理 ④ 底部主按钮「应用到预览」。
- **第 1 节提供「命名模板预设」**：模板框下方一行 **13 个内置预设芯片**（`time` `date` `week` `tq` `tq1` `rl` `wd` `xwd` `num` `bs` `hs` `xq` `sz`，顺序照作者给定）+ 末尾虚线「＋ 自定义预设」。**点一个预设即直接套用**：基名 + 自动序号后缀，**全稿统一停在 `tq`**：芯片选中态在 `tq`，模板框内容为 `tq_{seq}`，预览展开为 `tq_0.jpg`、`tq_1.jpg`……，面包屑「规则：`tq_{seq}`」与「预览按预设 tq 展开」、预设库预设名、右侧表格、底部摘要全部对齐同一个基名。
- **「预设库 · 新建 / 管理」内联面板**（静态呈现，不做弹窗）：预设名（基名，必填）+ 参数两列（**起始** 0 / 1、**补零**、分隔符）+ 「保存预设 / 取消」；面板字段用 `grid-template-columns: 34px 1fr 34px 1fr` 两列排布，标签列仅 34px，故标签统一写成 2 字（「起始」「补零」），否则会被压成两行；下方预设库列表 = 13 个内置 + 2 个自定义示例（`wl`、`sc`），每行右侧带编辑（`▤`）/ 删除（`✕`）图标，列表底部一行小字「自定义预设存在本机配置，可随「方案」导出；列表可滚动」。列表 15 条在静态稿里露出前 6 条，其余由列表自身滚动。
- 「工程安全命名」收成与变量芯片行同段的小按钮，保留可用：按安全规则一键改写模板，不改变预设选择。
- **序号规则是这一页的重点**：起始序号二选一，**默认「从 0 开始」**（可在设置中改为 1）；分隔符「自动补 `_`」；补零位数**默认「不补零」**（下拉档位顺序：不补零（默认）/ 最少 2 位 / 最少 3 位 / 固定 4 位，本稿演示默认档），下方小字写明依据「按素材实际写法：0–9 为一位，10 起自然进位（参考你的锁屏素材命名）」；序号位置**固定为后缀**（名称之后），设置中不提供前 / 后缀二选一；作用域「当前文件夹（默认）/ 当前分组 / 当前选中集」；「剥离原名中的序号」默认开。
- 中间表格的「新文件名」列做**字符级 diff**：灰色保留段（`.keep`）+ 蓝色新增段（`.add`）+ 红色删除线（`.del`）；演示组贴合作者素材的形态——模板 `tq_{seq}`、不从 0 补零，故为 `IMG_1234.jpg → tq_0.jpg` … `tq_29.jpg`（**30 行**：序号 0–29，前 10 行一位、第 11 行起两位）。顶部面包屑同步为「规则：`tq_{seq}`」+「预览按预设 tq 展开」，表格徽标为「前 30 / 128」。
- 本页画布独立加高到 **1600×1400**（仅本页页面级覆盖 `html, body, .win` 的高度；`tokens.css` 未动，01/02 仍为 900）。加高依据是**真实 Chrome DOM 探针实测**而非文本估算：1240 画布下 `.rule-body` 实测 `clientH = 1018px`、`contentH = 1159px`（① 命名模板 545 + ② 序号规则 291 + ③ 冲突处理 157 + ④ 落盘方式 117），装不下、④ 整组会被 `overflow:hidden` 裁掉，需 ≥ 1381px；1400 下可用升到 **1178px ≥ 1159px（余量 19px）**，四组规则全部可见、`.rule-ft` 的「应用到预览」贴底不裁切。文本估算（988px）系统性偏小约 171px，故高度审计一律以实测读数为基准。审计脚本（`docs/mockups/audit-rename03-height.js`）把探针实测读数**固化为基准常量**（画布 1240 / `clientH` 1018 / `contentH` 1159 / 四节 545·291·157·117），文本估算降级为对照，逐节差值超过 ±70px 时提示重新探针——静态估算不可信这件事，靠脚本而不是靠记性来守。中栏表格扩到 30 行（余量约 175px 落在表格与摘要之间）、「本次将应用的规则摘要」用 `margin-top:auto` 贴到中栏底部，避免加高后留出 300px 级空洞。
- 三种行状态：**第 4 行已单独剔除**（整行降级、复选框未勾选、序号列显示 `—`、不占号且其后各行顺位前移不跳号，见 7.3.3「剔除行不参与编号且不跳号」）、**第 8 行冲突（序号 7）**、**第 11 行超长（序号 10）**。
- 底部摘要面板给出「模板展开 / 序号与补零 / 预计写入」，并再次声明**预览基于草稿，磁盘尚未修改**。

### 04 变更集与关闭提醒
- 右侧抽屉按操作类型分组：重命名 18 项、移动 6 项、新建文件夹 2 项、移入回收站 1 项，每组都有「全部撤销」；合计 27 项与标题、底栏一致。
- 冲突项单独高亮，并写明冲突对象全路径（`目标已存在：01 产品渲染\产品渲染_003.png`）。
- **关闭前弹窗（本节最重要的一条交互约束）**：三个选项（提交并关闭 / 保存草稿并关闭 / 放弃变更并关闭）**无默认焦点、无「确定 / 取消」按钮、Esc 不关闭**，底部只留一行说明文字；危险选项用红色描边而非红色实心（不诱导点击）。规范依据见 8.4 危险操作确认规范。

### 05 外观自定义
- 左导航 + 中设置区 + 右「实时预览 + 当前取值」三栏；设置项改动即时反映到右侧微缩界面。
- 覆盖：主题模式（浅色 / 深色 / 跟随系统 / 按时间自动）、6 套预设主题、强调色、背景图（不透明度 / 模糊 / 平铺方式）、字体与字号缩放、信息密度、圆角、图标大小、**状态标记色（草稿 / 保护区 / 已整理 / 冲突四色）**、方案导入导出。
- 右侧微缩预览刻意做成**可辨识的三栏小界面**（顶部工具栏 + 左目录树 + 4×2 缩略图 + 右详情栏），而不是抽象色块——用户改字号 / 密度 / 圆角时要能立刻看出差别。
- 约束（见 9.3 约束）：外观设置**不得触发任何网络请求**（无网络字体、无 CDN）；危险弹窗样式**不可被主题改写**。
- **直通模式与「高级 / 危险」分区**：设置页必须显式划出「高级 / 危险」分区，「跳过变更集，操作立即生效」这一逃生开关（7.2）**只能**出现在该分区内，不得进入常规设置页或工具栏；开启时弹出危险级确认（8.4 红色样式，文案写明「此后软件内的改名 / 移动 / 删除将立即作用于真实文件，不再进入变更集」），开启期间底部状态条常驻警示标识（带文案「直通模式：操作立即生效」），该标识**不可被主题改写或隐藏**（7.2、9.3）。

### 06 保护区
- 12 张素材全部带锁标；一张同时具备「已确认 ✓ + 受保护」，两个徽标**分处右上与右下**并用文件名前的文字 ✓ 补充，避免挤在一个角上。
- 草稿态素材仍以橙点 + 琥珀徽标表达——**受保护不等于不会出现在草稿里**（手动单条操作允许，但需二次确认）。
- 右栏四段：说明与开关（**「提交后自动加入保护区」默认开启**）、计数统计（保护区内 210 / 本周新增 12）、最近整理记录（可一键跳回对应变更集撤销）、保护区规则（跳过范围 / 例外 / 同步方式）。
- 底部状态条与左栏都显示「保护区 210」，批量操作命中受保护项时给出「已跳过 N 项（受保护）」的显式提示；该提示旁必须有显式一次的「**本次包含受保护项**」按钮（7.6）——它是一次性开关、不解除保护，点击后本次计划以警示色标记，并在最终预览与整理报告中留痕（记录「本批次包含受保护项 N 项」）。

### 07 文件夹视图 · 混排列表（**默认视图**）
- **视图切换为四档**：文件夹（默认）/ 网格 / 列表 / 详情，快捷键 `Ctrl+1/2/3/4`（8.3）。「文件夹」置于首档，01 / 02 的工具栏同一组也含这一档，两稿仍分别停在网格 / 列表，便于对照。
- **文件夹成为一等操作单元**：文件夹行分组排在文件行之前，列 = 名称 ｜ 类型 ｜ **项数 / 大小** ｜ **整理进度** ｜ 修改时间 ｜ 状态——「这个文件夹还剩多少没整」不进文件夹就能看到（对应 8.5 的六项信息要求）。
- **拖拽到文件夹行即移动**：`商业拍摄` 行显示落点高亮 + 「松开即移动到此处」，且**先进变更集**，提交前磁盘零变化。
- **文件夹自身的增删改也是草稿**：`新建文件夹` 行为草稿态（斜体 + 橙点 + 「草稿 · 待命名」，名称可编辑）；`海边日落` 带「草稿 2」徽标；`2026 冲绳` 带锁标「受保护」。
- 左栏目录树每行带展开箭头、待整理数（分支行 `待整理 128`、叶子行 `40/46`）与 6 px 迷你进度条；文件夹子工具条给出「新建文件夹 / 移到… / 批量重命名 / 全选」与「显示 / 整理进度」筛选。
- 右栏（选中单个文件夹）：包含项数与类型分布、总大小、修改时间、受保护项数、整理进度、待提交变更（可逐条撤销）、文件夹操作、整理建议，以及**红色危险区**（移入回收站，文案含项数）。
- 文件区底部一句「其余 115 个文件可在原地滚动查看，或切到「列表」视图」——说明这里是**同一目录的两段**，不是两个页面。

### 08 文件夹视图 · 卡片墙 + 多选批量
- 顶部两级分段：**视图**（文件夹 / 网格 / 列表 / 详情）+ **子模式**（列表 / 卡片），即 8.5 的两种子模式。
- **文件夹卡** = 2×2 缩略图拼贴 + 左上文件夹标 + 右上项数徽标 + 名称 + 细进度条 + 状态；四张卡覆盖四种状态：`海边日落`（87% + 草稿 2）、`商业拍摄`（拖入高亮「+ 移动到此」+ 待提交 3）、`2026 冲绳`（100% + 受保护）、`新建文件夹`（草稿态 · 待命名）。
- **文件卡**复用 06 的三态编码（草稿橙点 / 已整理 ✓ / 受保护锁）。
- **多选文件夹 → 右栏切换为批量面板**：标题写明「已选 2 个文件夹 · 68 项素材」并列出所选；操作为 重命名规则… / 移动到… / 加入分组 / 加入保护区 / 导出清单（生成 CSV / TXT）；附统计与变更类型分布；并显式提示「选中的 2 个文件夹含 1 项受保护素材，批量操作会默认跳过」。

## 三、令牌体系与 Tailwind 的对应

- 视觉唯一真源是 `docs/mockups/tokens.css` 里的 **CSS 变量**（颜色 / 间距 / 圆角 / 字号 / 阴影 / 动效时长），组件类只允许引用 `var(--*)`，**禁止写死色值**（自检脚本会扫内联样式里的十六进制）。
- 允许引入 Tailwind CSS、animate.css 一类第三方样式库，落地约定见《鹿铃 · 开发需求文档（执行版）》**12.4 样式与前端依赖策略**：Tailwind 主题必须映射到同一批 CSS 变量（`theme.extend.colors` 指向 `var(--*)`），关闭 preflight 或用 `@layer` 收敛，animate.css 用 `--animate-duration` 全局压到 ≤250ms；**所有样式库本地打包，禁止 CDN**。
- 稿子里的微缩预览等「颜色即内容」的色块（预设主题缩略色、强调色取样）允许字面色值，属自检白名单。
- 静态自检对 01 / 02 / 03 三页全部通过：结构、内联色值、页面 CSS 字面色值、非法符号、应用名五项。

## 五、评审要点（请重点确认）

1. **三栏骨架与 240px 侧栏**是否符合你的使用习惯？中间区的信息密度是否可接受？
2. **三态视觉编码**（真实 / 草稿 / 已整理 / 受保护 / 冲突）能否一眼分清？是否需要更醒目或更克制的方案？
3. **03 的重命名页**：字符级 diff、序号默认 0 且不补零、剔除行不跳号，是否符合预期？
4. **04 的关闭弹窗**：无默认焦点、无确定 / 取消，是否会让你觉得难以操作？
5. **05 的可自定义项**是否够用？还有哪些外观维度希望开放（例如标签栏位置、缩略图比例、动画开关）？
6. **深色主题**是否需要更多预设（当前 6 套）？
7. **文件夹视图（07 / 08）**：文件夹行要暴露的六项信息（项数 / 大小 / 整理进度 / 草稿与待提交徽标 / 保护状态 / 被引用状态）是否够用、是否过多？「拖拽到文件夹行即移动」是否符合直觉？卡片墙的文件夹卡（2×2 拼贴 + 进度条）与混排列表你更常用哪一种？主工具栏的视图切换为**图标**四档（文件夹 / 网格 / 列表 / 详情），08 的子模式用的是**文字**分段——要不要把主工具栏也改成文字（更直白、但更占宽）？
