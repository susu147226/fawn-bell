# 鹿铃 0.1.20

## 修复：新增的界面文案一律显示为空

程序对超出范围的字符串编号直接返回空串，而这个范围的上限**没有跟着新条目上移**。
结果是 0.1.18 起新增的文案全部解析为空——功能都在，只是**按钮上一个字也没有**：

- 更新失败时的「手动下载」与各类失败原因
- 命令面板里的「重置窗口位置」「刷新缩略图缓存」
- 网络共享的登录对话框

现在上限已修好，并加了编译期断言，以后忘记上移会直接编不过，而不是变成空白标签。

## 修复：应用内更新一直卡住

在应用里检查到新版本、下载完成后点安装，界面会一直停在「正在安装」，**实际上什么
都没发生**。

原因是：应用给下载好的安装包传的仍是 **Inno Setup 的静默开关**
（`/VERYSILENT`、`/SUPPRESSMSGBOXES`、`/DIR=` 等），而安装包早已换成 **NSIS**
（只认 `/S` 与 `/D=`）。安装器不认这些参数，于是按**普通向导**启动——偏偏这次启动
用的是隐藏方式，窗口没人看得见、也没人能点；应用又在等它退出，于是永久停住。

现在改传 `/S /D=<安装目录>`。

同时补上换安装器时丢掉的另一半：**旧的安装器会在静默更新后把应用重新拉起来**，NSIS
脚本没有这段逻辑，所以即便不卡，更新完应用也不会自己回来。现在安装结束前会用
`explorer.exe` 以登录用户身份把应用拉起（不会留下一个提权运行的文件管理器）。

> **这一版需要你手动安装一次**：0.1.19 里的更新程序本身是坏的，所以从 0.1.20 起
> 应用内更新才会正常工作。

## 修复：四个预览增强包全部下载不下来

预览增强包（视频/音频、HEIF 与 RAW 图像、压缩包）的下载地址全都指向
`susu147226/fawn-bell` 的 **v1.0.53** 发布，而这个仓库从来没有那个 tag——四个包在
项目改名并接管底座时就一起失效了，用户只会看到「下载不下来」。

现在把上游的同一批构建产物转存为本仓库的 **`packs-1.0.1`** 发布，17 个资产的
SHA-256 与程序内置的目录清单逐个核对一致，程序端无需改动哈希，只把地址指过来。
四个包此后都能正常下载安装。

## 新增：设置里「一次装齐全部预览包」

预览增强包分区末尾多了一个按钮，一次把当前缺少的包都开始下载，不必逐个点。
已在磁盘上的包会跳过，同时下载期间按钮置灰。

- `Luling-0.1.20-portable-win-x64.zip`
