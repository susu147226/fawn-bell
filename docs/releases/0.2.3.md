# 鹿铃 0.2.3 · 拖得动，删得快

这次修的都是手感上的事 —— 用起来别扭、但看代码又瞧不出来的那种。

## 把文件拖到程序上，现在真的会用它打开

以前把文件夹拖到列表里 `Visual Studio Code.lnk` 上，我只弹出提示、松手却什么也不做。
原因是拖到文件行时我一律当成「拖到当前文件夹」，而那个文件通常就在当前文件夹里，
等于把文件移动到自己身上 —— 白忙一场。

现在：拖到 `.exe`，或者指向程序的快捷方式上，松手就用它打开，拖过去的文件全部作为
参数传给它。指向**文件夹**的快捷方式保持老规矩（移动进去），和资源管理器一致。

## 拖到列表边缘，列表会自己滚

想把文件丢进当前看不见的文件夹，以前只能先滚到位再拖。现在拖着文件靠近列表上下
边缘，列表会跟着滚，和资源管理器一样。

## 一次拖很多文件不再卡

这个毛病是上一版我自己引入的：给拖拽加边缘滚动时，那段判断写在了**每次鼠标移动**
都会执行的地方，而它每次都要算一遍列表的位置。拖一个文件还好，一次拖几十个、
快速划动时，每秒上百次的计算把主线程占满 —— 于是拖动卡顿、偶尔像死机，
**拖到浏览器或网页的上传区也收不到文件**（对方来要数据时我没空应答）。

现在这段判断节流到 80 毫秒一次 —— 滚动跟上眼睛就够，不必跟上鼠标。拖到浏览器、
VS Code 这些接收方也就恢复正常了。

## 批量删除快多了

以前删 N 个文件，就要**重建 N 次** shell 的删除设施：回收站对象、传输源、进度接收器，
或者永久删除时的整个 `IFileOperation`，甚至还各自单独执行一遍。

现在这些东西**整批共用一份**，最后统一执行一次。文件越多，省下的越多。
（删除的判定逻辑没动：仍然是遇到第一个错误就停下，仍然逐个核对文件是否真的消失。）
