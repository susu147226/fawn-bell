## 一、项目定位与目标

一个运行于桌面端的**本地素材整理应用**。用户指定一个或多个「素材根目录」，工具自动获取其中素材，按规则整理其**命名**与**存放位置**，支持**分组批量操作**与**完整的文件 / 文件夹管理操作**，并且——**在用户确认之前，不触碰真实文件夹**。

核心目标：

1. **虚拟优先，一次落盘**：软件内看到的一切改名、移动、新建、删除都先是「草稿」（虚拟变更集）；确认提交或关闭软件时被提醒，用户确认后才真正写盘。这让「就地整理」从高风险操作变成可反复试排的沙盘。
2. **开盒即用**：绿色版解压即运行，安装版一次安装即可用，两者都不装额外运行时、不联网、不登录。
3. **批量而非单个**：以「文件夹 / 分组 / 选中集」为工作单位；同时保留对单个素材的精细操作。
4. **安全默认**：删除只进回收站；同名冲突永不静默覆盖；一切写操作写完 journal，可撤销。
5. **好看且可自定义**：界面美观、布局合理，外观可深度自定义（主题、强调色、背景图、密度、字体）。
6. **轻便快捷**：启动快、运行时内存占用低、常规规模（2000 张以内）操作无等待感。
   - 【已确认 第 1 条（v1.1）】「轻便快捷」**不再包含程序体积指标**：体积不设上限，该目标由冷启动、内存占用与操作响应三项承载（第九节）。

核心流程：

```
选择素材根目录（可多个）
      ↓
扫描建索引（SQLite，只读真实文件）
      ↓
分组 / 筛选 / 选中（虚拟分组、智能集合、保护区）
      ↓
全部编辑动作进入【虚拟变更集】——此时真实文件夹未发生任何改变
   · 重命名（含序号规则）  · 移动 / 复制 / 新建 / 删除
   · 可随时撤销草稿（Ctrl+Z 只删草稿，不碰磁盘）
      ↓
点「提交」→ 生成执行计划 → 最终预览（逐条 diff）→ 二次确认
   （或：关闭软件时弹提醒 → 确认后提交）
      ↓
执行 + 写 journal + 生成整理报告（可撤销）
      ↓
已整理的素材打「已整理」标记，默认进入【保护区】
```

## 四、素材类型与识别规则

### 4.1 五类素材

| 类别 | 扩展名（主要） | 说明 |
| --- | --- | --- |
| **图片 image** | jpg / jpeg / png / webp / gif / bmp / tif / tiff / avif / heic / heif / svg / ico / psd / psb / ai / eps / raw 系（cr2 / cr3 / nef / arw / dng / raf / orf / rw2） | 主类型。缩略图优先走系统缩略图接口，RAW 与 HEIC 依赖系统解码器 |
| **视频 video** | mp4 / mov / mkv / avi / webm / m4v / flv / wmv / mpg / mpeg / ts / m2ts / r3d / braw | 仅取元数据，不做转码 |
| **音频 audio** | mp3 / wav / flac / aac / m4a / ogg / opus / wma / aiff / mid | 仅取元数据 |
| **3D 工程 3d** | blend / blend1 / max / fbx / obj / mtl / stl / gltf / glb / c4d / ma / mb / hip / hipnc / ztl / ztn / zpr / spp / sbsar / sbs / abc / usd / usda / usdc / usdz / skp / 3dm / step / stp / iges / igs / dwg / dxf / f3d / sldprt / sldasm / uasset / umap / unity / prefab | 见 4.3「工程包」 |
| **文档 doc** | pdf / doc / docx / xls / xlsx / ppt / pptx / txt / md / rtf / csv / json / xml / yaml / epub / mobi / one / pages / numbers / key | 仅索引，不解析正文 |

- 未识别扩展名归入 `other`，仍可被索引、改名、移动，只是不参与「按类型」的智能分类与缩略图。
- 素材类型判定**以扩展名为准，辅以文件头嗅探**（改错扩展名的文件应被纠正归类并提示）。
- 扩展名清单**必须可由用户在设置中增删**（不同工作流差异极大），配置文件为 JSON，存放在应用数据目录（第十二节第 1 条）。

### 4.2 忽略与排除

- 默认忽略：隐藏文件、`.` 开头、`Thumbs.db`、`.DS_Store`、`desktop.ini`、`~$*`（Office 临时锁文件）、`*.tmp`、导出/输出目录自身（指用户自建的导出目录）。
- **默认排除应用数据目录（索引库、缩略图缓存、journal、日志）自身**，即使它被放在某个素材根之下（见第十二节第 2 条）。
- 默认**不跟随**符号链接与 junction（防成环与越界）；提供显式开关。
- 云占位文件（OneDrive / 坚果云等）：检测 `Offline` / `RecallOnDataAccess` 属性，**默认只读元数据、不下钻内容**，避免误触发全量下载；这类文件在界面上以云朵角标标记。

### 4.3 工程包与伴随文件（3D / 设计素材专用）

3D 与设计工程文件几乎从不单独存在，必须识别「工程包」，否则会造成工程损坏。

| 概念 | 示例 | 处理 |
| --- | --- | --- |
| **伴随文件** | `model.blend` + `model.blend1`；`scene.max` + `scene.max.bak`；`mat.sbs` + `mat.sbsar`；`tex.ztl` + `tex.ztn` | 视为同族，一起选中、一起改名、一起移动；改名时保持配对关系 |
| **同名依赖目录** | `scene.fbm/`（3ds Max 位图目录）、`scene.max_files/`、`model_tex/` | 移动工程文件时**默认连同依赖目录一起移动**，并在预览中明确列出 |
| **工程目录** | Unity `Assets/`、Unreal `Content/`、Blender 项目的 `textures/` | 若工作根本身是工程目录，**默认限制为只读索引 + 不改名**，需显式解锁 |

- **工程文件移动可能破坏工程内部的绝对/相对引用**。v1 的处理是**警告而非解析**：移动工程文件时提示「该类型文件可能包含对贴图与缓存的路径引用，移动后请在原软件中验证」，并在报告中留档。
- 解析工程内部引用（.blend / .max / .ma 内部路径表）**不进入 v1**，列为 v2 备选。
- 文件名中的**非法字符与长度**对工程文件尤其敏感（有些引擎拒绝含空格或中文的路径）→ 提供「工程安全命名」预设：仅 ASCII、无空格、无中文、≤64 字符。
- **与「素材树零写入」的边界**【已确认 第 4 条（v1.1）】：本节的伴随文件与同名依赖目录属于**素材本体或其组成部分**（由作者的原始素材所携带、原软件所生成），**不受**第十二节第 1 条「不得留下非素材伴随文件」的约束；软件自己的元数据不得以任何形式混入其中。

#### 4.3.1 引用感知与被引用文件保护【新增，D31；由查看作者真实素材后提出，待作者确认】

华为锁屏主题这类工程包中，配置文件按**文件名**引用图片：作者真实素材 `D:\desktop\code\旷野之息-ovhr-Eason-萌萌\锁屏\huawei\unlock\lockscreen\manifest.xml`（125 行）就引用了 `bj.png`、`top.png`、`wallpaper.jpg`。改动这类文件的名字会让工程包在目标软件里失效。

- **建索引（扫描期）**：对每个素材目录，解析**同目录与上溯目录**（上溯至工作根为止，不越界、不跟随符号链接、跳过应用数据目录）中的 `*.xml` / `*.json` / `*.txt` / `*.js` / `*.css` / `*.html`，按文本提取其中的**文件名**，建立「**文件名 → 引用它的文件**」映射（含命中行号），写入本地库，**不落素材树**。
- **命中判定**：批量改名 / 移动的草稿生成时，逐条判定目标是否为被引用文件。
- **默认行为（安全）**：**只警告并列出引用方**（文件路径 + 行号 + 原文），**不自动改写引用**；预览页与状态条给出「该文件被 N 处引用（工程包 / 主题包可能因此失效）」条目，报告留痕。
- **可选行为（高危）**：「**同步改写引用**」是独立选项，**默认关闭**；开启后：
  1. 改写动作**进入虚拟变更集**（与文件改名同批次），不直写磁盘；
  2. 提交前**必须二次确认**（危险级红色样式，6.4）；
  3. 预览中**逐条列出将被改写的引用行**（文件 + 行号 + 旧文本 → 新文本），可逐行取消；
  4. 整理报告单列「改写引用 N 行」。
- **边界**：仅做**文本级文件名匹配**（不解析二进制工程文件的内部路径表，与 4.3 既有边界一致）；该映射是**索引**而非真源，索引缺失时退化为不提示，不做猜测式改写。
- **工作量**：**+1.0 人日**，并入 P3（5 → **6.0**）。

### 5.1 扫描与索引（F1）

- 递归扫描选定根目录，建立 SQLite 索引；支持**增量扫描**（按 `体积 + 修改时间 + 创建时间` 判定变更）。
- **扫描是只读的**，任何情况下不修改被扫描的文件。
- 深度、包含/排除通配符、是否跟随链接、是否读取云占位内容，均可配置（第八节）。
- **应用数据目录强制排除在扫描范围之外**（第十二节第 2 条）；该排除项不出现在用户可编辑的忽略规则列表里，属于不可关闭项。
- 首次扫描显示进度与预估剩余时间；可随时取消（取消只丢弃本次结果，不影响已建立的索引）。
- 扫描结果按 `kind` 分类统计，界面顶部显示「图片 1,820 · 视频 96 · 音频 34 · 3D 210 · 文档 402 · 其他 18」。
- 已消失的文件（索引后被外部删除/移动）标记为 `missing`，以灰色显示并提供「从索引移除」与「重新扫描」两个动作，**不自动清理**。
- 扫描期同时建立 4.3.1 的**文件名引用映射**（同目录与上溯目录中的配置文件），与索引同批完成，不额外遍历素材树。

### 5.2 虚拟变更集与提交模型（**本版核心机制**）

**条文：软件内对文件与文件夹的一切修改动作，均不立即作用于真实文件系统，而是写入「虚拟变更集」。真实文件仅在用户显式提交（或在关闭软件时被提醒并确认）后统一变更。**

- **草稿态（draft）**：改名、移动、复制、新建文件夹、重命名文件夹、删除（标记为待删除）等动作全部累积在变更集中。此时磁盘**零写入**。
- **投影视图（projected view）**：界面展示的树与列表是「真实状态 + 待提交变更」的投影。一条 `A.jpg → B.jpg` 的草稿，在界面上立即显示为新名字与新路径。
- **实时预检**：每条草稿加入时立即做冲突检测（目标已存在于真实磁盘 / 与另一条草稿冲突 / 名字非法 / 路径超长 / 超出工作根），在行内以角标与颜色标注，并在底部状态条汇总「待提交 M 项，其中 K 项有问题」。
- **草稿撤销**：`Ctrl+Z` / `Ctrl+Y` 在草稿上下文内即撤销/重做一条草稿，**不触碰磁盘**。这是本机制带来的最大安全收益。
- **视觉编码**（三态必须可区分）：

| 状态 | 含义 | 视觉 |
| --- | --- | --- |
| 真实态 | 磁盘当前状态，未排入任何变更 | 常规样式 |
| 草稿态 | 已排入变更集，尚未落盘 | 斜体 + 左上角橙色小圆点 + 悬浮提示新旧名对照 |
| 已整理态 | 已提交落盘（曾参与过批次） | 右下角 ✓ 徽标 + 悬浮显示整理时间与批次号 |

- **提交（Commit）**：点「提交」→ 生成执行计划 → **最终预览**（逐条 `旧 → 新`、移动、新建、删除的完整清单，含跳过项与原因）→ 二次确认 → 执行。执行细节见 5.9、5.10。
- **分批提交**【建议】：变更条目超过阈值（默认 500）时，允许按分组或按批次分批提交，降低单次风险。
- **关闭软件时的提醒**（作者明确要求）：若变更集非空，关闭时弹出对话框，**三个选项必须并列且写清后果，不设默认焦点，不响应回车**：

| 选项 | 行为 |
| --- | --- |
| **提交并关闭** | 先执行完整提交流程（含最终预览与二次确认），成功或按失败策略处理完毕后再退出 |
| **保存草稿并关闭** | 变更集持久化到本地库（应用数据目录，**不写素材目录**），真实文件不变；下次启动时恢复并提示「上次有 N 项未提交变更」 |
| **放弃变更并关闭** | 清空变更集，真实文件不变（此选项需二次确认） |

> 「保存草稿并关闭」**已确认为正式选项**【已确认 第 8 条】：草稿持久化于库中、不碰素材，风险低，因此不缩减关闭对话框的选项数。

- **删除类变更的特殊规则**：变更集中只要包含删除，无论何时提交，都必须在最终预览中**单独列出删除项并要求独立二次确认**，文案明确写「移入回收站」。
- **崩溃与非正常退出**：因为草稿只存在于本地库，**崩溃不会损坏任何素材**；下次启动自动恢复草稿并提示。
- **立即应用开关（逃生开关）**【已确认 第 5 条（v1.1），**保留，默认关闭**】：设置中提供「跳过变更集，操作立即生效」（默认**关闭**），供想立刻落盘的场景使用；开启时该操作直通「计划 → 预览 → 执行」并写 journal。**三项强制约束**：
  1. **位置受限**：该开关只能出现在设置的「高级 / 危险」分区，不得出现在常规设置页或工具栏，避免被顺手打开；
  2. **强确认**：开启时弹出危险级确认（6.4 红色样式），文案必须写明「此后软件内的改名 / 移动 / 删除将立即作用于真实文件，不再进入变更集」；
  3. **常驻警示**：开启期间底部状态条常驻醒目标识（警示色 + 文案「直通模式：操作立即生效」），且不可由主题改写或隐藏。
  4. 关闭开关后，仍在变更集中的草稿不受影响；切换动作本身不触发任何落盘。
- **提交预检清单**（提交前必须全部通过或明确选择忽略）：目标路径合法、工作根内、无环状改名、无未解决冲突、无受保护项被改动、目标盘可写、目标盘剩余空间满足复制需求。

### 5.3 命名与序号规则（F2）

#### 5.3.1 模板占位符

| 占位符 | 含义 | 示例输出 |
| --- | --- | --- |
| `{name}` | 原文件名（不含扩展名） | `海边日落` |
| `{ext}` | 扩展名（不含点） | `jpg` |
| `{seq}` | 序号（规则见 5.3.2） | `0`（10 项以内的组） |
| `{date}` / `{time}` | 日期 / 时间（优先拍摄时间，无则文件修改时间） | `20260928` / `142530` |
| `{camera}` | 相机 / 设备型号 | `ILCE-7M4` |
| `{w}` / `{h}` | 像素宽 / 高 | `6000` / `4000` |
| `{group}` | 所属分组名 | `旅行` |
| `{parent}` | 上级目录名 | `DCIM` |
| `{kind}` | 素材类别名 | `image` |
| `{hash8}` | 短哈希（需开启去重） | `a1b2c3d4` |
| `{counter:3}` | 全局计数器（跨文件夹连续，补零 3 位） | `000` |

> 注：上表 `{seq}` 的示例按 5.3.2 的**自适应补零**与**默认「从 0 开始」**取值——10 项以内的组首个输出即 `0`（不补位）；组内超过 10 项时按最大序号值的位数自动扩位（见 5.3.2 判定表）。`{counter:3}` 已显式指定 3 位，故恒为 `000`。若把起始值切到 1（作者要求保留的选项），`{seq}` 的首个输出相应为 `1`。

- 修饰符：`:YYYYMMDD`、`:HHmmss` 日期格式；`_lower` / `_upper` / `_title` 大小写；`_slug` 转 URL 安全；`_trunc:N` 截断；`{seq:3}` 固定补零位数（**单条模板层显式覆盖设置值**）；`{name|[回退文本]}` 空值回退。
- 空值安全：任何占位符解析为空时，**默认回退到上一级可用值**（拍摄时间→修改时间→创建时间），绝不允许输出空名或只剩扩展名。
- 非法字符处理：`\ / : * ? " < > |` 与保留设备名（`CON`、`PRN`、`AUX`、`NUL`、`COM1-9`、`LPT1-9`）替换为 `_`；**结尾的空格与点号必须剥离**（Windows 会静默丢弃，导致「改了但名字不对」）。
- Unicode：统一 **NFC 规范化**后比较与写入，避免伪重名。
- 原名清理开关：空格转 `_` / 转 `-` / 保留；合并连续分隔符；去除首尾分隔符；**连续数字压缩**（可选，如 `IMG_0001_2` → `IMG_1`）。
- 名称长度：默认上限 120 字符（不含扩展名），超出时**截断中间段并保留结尾识别信息**，在预览中标红提示。
- **「工程安全命名」预设**：仅 ASCII、无空格、无中文、≤64 字符（供 3D 工程文件使用，见 4.3）。

#### 5.3.2 序号规则（作者明确的补充要求）

| 规则项 | 选项 | 默认 |
| --- | --- | --- |
| **起始值** | **从 0 开始 / 从 1 开始**（作者要求提供选择，两者必须都可用） | **从 0 开始**【已确认 第 3 条（v1.1）】 |
| **序号前分隔符** | **自动补 `_`**（作者明确要求）；可选 `-` / 空格 / 无 | **自动补 `_`** |
| **分隔符智能处理** | 相邻字符已是 `_` 或数字时不重复插入 | 强制生效 |
| **补零位数** | **自适应（默认）** / 固定 1–6 位（设置页至少提供「固定 2 位」「固定 3 位」两个快捷档） | **自适应**【已确认 第 10 条】 |
| **序号位置** | **固定为后缀（名称之后）**，不提供设置；命名模板里的 `{seq}` 位置不受此限 | **后缀（固定）**【已确认 第 12 条 / 作者 `m00595`】 |
| 序号作用域 | 当前文件夹 / 当前分组 / 当前选中集 | **当前文件夹**【已确认 第 2 条】 |
| 原名序号剥离 | 不剥离 / 剥离尾随数字 / 剥离尾随 `_数字` / 按正则剥离 | **剥离尾随 `_数字`**【已确认 第 3 条】 |
| 条目增删后重排 | 实时重排（草稿态下免费）；**剔除行不参与编号且不跳号** | 开启 |

- **「补零位数 = 自适应」的定义**【已确认 第 10 条】：**位数 = 组内最大序号值的十进制位数**（不是简单地按「组内条目数」取位数——两者在起始值不为 0 时结果不同）。判定表：

| 起始值 | 组内序号范围 | 最大序号值 | 位数 | 输出示例 |
| --- | --- | --- | --- | --- |
| 0 | 0–9（组内 ≤10 项） | 9 | **1 位** | `海边日落_0.jpg` … `海边日落_9.jpg` |
| 0 | 0–99（组内 ≤100 项） | 99 | **2 位** | `海边日落_00.jpg` … `海边日落_99.jpg` |
| 0 | 0–127（组内 128 项） | 127 | **3 位** | `海边日落_000.jpg` … `海边日落_127.jpg` |
| 0 | 0–128（组内 129 项） | 128 | **3 位** | `海边日落_000.jpg` … `海边日落_128.jpg` |
| 1 | 1–9（组内 ≤9 项） | 9 | **1 位** | `海边日落_1.jpg` … `海边日落_9.jpg` |
| 1 | 1–10（组内 10 项） | 10 | **2 位** | `海边日落_01.jpg` … `海边日落_10.jpg` |

- **设置项形态**【已确认 第 10 条】：设置页提供「**自适应（默认）** / 固定 2 位 / 固定 3 位」，并允许在高级项中自定义 1–6 位。固定档**覆盖**自适应结果——包括「固定 2 位」在组内只有 10 项时输出 `_00`…`_09`（位数多于自适应）的情形，预览与报告必须如实呈现，不得静默改回自适应。
- **阈值的位数取整规则**：位数只由**组内最大序号值**决定；起始值 / 作用域 / 剔除行变化导致最大序号值变化时，位数**随之重算**（草稿态下免费重排）。

- **剔除行不参与编号且不跳号**（对应 UI 设计稿 03 的三种行状态之一）：批量计划中被用户单独剔除（逐行取消勾选）的条目**不占用序号**，其余条目序号保持连续、不产生空号。示例：`0 / 1 / 2 / 4` 在剔除序号 `4` 那一行后重排为 `0 / 1 / 2 / 3`（组内 10 项以内，1 位；若位数因重排而变化，序号文本同步重算）。该规则与起始值 0 或 1 无关，切换起始值不改变「不跳号」这一取向；剔除只影响编号，不影响已排草稿。

- 【已确认 第 3 条（v1.1）+ 第 10 条】**起始值默认 0 的三点自洽要求**：
  1. **首个序号是 `0` 而不是 `1`**：默认「补零位数 = 自适应、起始值 0」下，10 项以内的组序号依次是 `0`、`1`、`2`…；组内 11–100 项（最大序号 ≥10）时扩到 2 位（`00`…`99`）；最大序号 ≥100 时扩到 3 位（`000`…）。
  2. **UI 必须给出实时预览**：设置页与批量预览中，起始值 / 补零位数 / 序号作用域任一变动，都必须**立即**渲染出前三项的最终文件名（如 `海边日落_0.jpg`），避免用户把 `0` 误读为「空序号」或误判位数。命名模板输入框下方常驻一行预览。
  3. **0 / 1 都是合法选项**：作者原始要求是「提供选择」，因此不得因为默认值改为 0 而移除「从 1 开始」；切换后在预览与报告中如实反映（含自适应位数的重算，如 1 起算的 10 项组输出 `_01`…`_10`）。

示例（**默认配置：起始值 0、补零自适应；自动附加的序号固定为后缀**）：

| 原名 | 结果 |
| --- | --- |
| `IMG_1234.jpg`、`IMG_1235.jpg`（同文件夹 2 张，最大序号 1） | `IMG_0.jpg`、`IMG_1.jpg` |
| `海边日落 (1).jpg`、`海边日落 (2).jpg`（同文件夹 2 张） | `海边日落_0.jpg`、`海边日落_1.jpg` |
| 起始值改为 1（同 2 项，最大序号 2） | `海边日落_1.jpg`、`海边日落_2.jpg` |
| 模板层写法：把 `{seq}` 写在名称之前（起始值 0，2 项） | `{seq}_海边日落` → `0_海边日落.jpg`、`1_海边日落.jpg`（**模板变量位置不受限制**；它是模板层能力，与「序号位置固定为后缀」互不影响） |
| 组内 10 项（起始值 0，最大序号 9） | `海边日落_0.jpg` … `海边日落_9.jpg`（**1 位**） |
| 组内 11 项（起始值 0，最大序号 10） | `海边日落_00.jpg` … `海边日落_10.jpg`（**2 位**） |
| 组内 100 项（起始值 0，最大序号 99） | `海边日落_00.jpg` … `海边日落_99.jpg`（**2 位**） |
| 组内 120 张（起始值 0，最大序号 119） | `海边日落_000.jpg` … `海边日落_119.jpg`（**3 位**） |
| 组内 128 项（起始值 0，最大序号 127） | `海边日落_000.jpg` … `海边日落_127.jpg`（**3 位**） |
| 组内 10 项但补零切到「固定 2 位」 | `海边日落_00.jpg` … `海边日落_09.jpg`（固定档覆盖自适应） |
| 原名含序号 + 已剥离（起始值 0，2 项） | `素材_001.jpg` → `素材_0.jpg` |
| 原名含序号 + 已剥离（起始值 0，2 项） | `素材_001_v2.jpg` → `素材_v2_0.jpg`（剥离尾随 `_数字` 段 `_001`，保留 `v2`） |

#### 5.3.3 单独操作与批量操作的并存

- **单个素材操作**：内联重命名（`F2` 就地编辑，回车生效为草稿）、单条「按模板重命名」、单条移动/复制/删除、单条标签与分组调整。
- **部分选中**：`Ctrl` 点选、`Shift` 连选、框选、`Ctrl+Shift+A` 反选、按条件全选（如「选中本文件夹所有 png」）。
- **从批量预览中单独剔除**：批量计划生成后，可在预览表中**逐行取消勾选**，被取消项不参与本次提交；同时提供「仅保留选中行」的快捷操作。
- 单条操作与批量操作走**同一条管线**（草稿 → 预检 → 提交），不存在两套逻辑，避免行为不一致。

### 5.4 归档与位置整理（F3）

- **目录模板**：`{kind}/{yyyy}/{mm}`、`{group}/`、`{date:yyyy-MM}`、`{camera}/{yyyy}` 等，支持与命名模板相同的占位符与修饰符。
- **同盘移动**：元数据操作，瞬时完成，不搬运数据。
- **跨盘移动**：复制 → 校验（体积 + 修改时间，可选哈希）→ 删除源 → 写 journal；中断残留默认「保留源、删除不完整目标」。
- **复制模式**：目标已存在同名时，比对体积与时间；完全相同 → 视为重复，跳过并记录；不同 → 按冲突策略处理（加后缀 / 跳过 / 中止批次），**绝不静默覆盖**。
- **空目录清理**：归档后可选清理空目录，默认**关闭**；执行前必须列出将被删除的目录清单。
- **撤销移动**：受 journal 支持，跨盘移动的撤销是「移回 + 清理目标残留」。
- **工程包整体移动**：命中 4.3 规则的工程文件，其伴随文件与同名依赖目录默认同步移动（可在预览中逐项取消）。
- **被引用文件**：命中 4.3.1 引用映射的移动 / 改名，默认只警告并列出引用方（见 4.3.1）。

### 5.5 分组（F4）

| | 虚拟分组（默认） | 物理分组 |
| --- | --- | --- |
| 本质 | 索引库中的标签 / 集合 | 真实移动文件到子文件夹 |
| 是否移动文件 | 否 | 是（走草稿 → 提交） |
| 一个素材属于几组 | 可多个 | 只能一个位置 |
| 适用 | 日常归类、跨目录筛选、批量操作选中集 | 交付、归档、供其他软件按目录读取 |

- 分组类型：**静态分组**（手工挑选或按标签）、**智能集合**（保存一条规则，每次打开动态求值，新增素材自动落入）。
- **内置智能集合**：随程序提供「重复内容」（5.12）等内置集合；内置集合可另存为自定义集合后修改。
- 分组支持：新建、重命名、改色、排序、嵌套一层、删除（**删除分组不影响素材**，仅解除关系，需明确提示）、拖拽素材入组、从分组生成批量操作。
- **物理分组 = 虚拟分组 + 归档规则语法糖**：把分组名代入目录模板执行一次归档，不另写代码。
- **分组数据一律存于本地库（应用数据目录）**【已确认 第 4 条（v1.1）】：v1.0 中「是否额外落盘为素材旁的 `.tags.json` 侧车文件」这一待确认项**已被第 4 条批复终结**，不再作为选项存在。素材目录内不会出现任何标签、分组或元数据文件（第十二节第 1 条）。
  - 因此分组的可移植性由**库的导出 / 导入**承担（11.4）：导出包内含分组、标签、保护区、规则方案与素材清单指纹，可在另一台机器上导入并按指纹重新关联。

### 5.6 保护区（F8，作者明确的补充要求）

**定义：保护区是一组「不允许被批量操作改动」的素材集合，横切于分组与目录结构之上。**

- **自动加入**：素材的变更被**成功提交**后，自动打上「已整理」标记并加入保护区。**默认开启**【已确认 第 6 条（v1.1）】，可在设置中关闭（第八节「安全」分组同名开关）。
- **手工加入 / 移出**：右键菜单「加入保护区 / 移出保护区」、快捷键 `Ctrl+Shift+L`、批量选中后一键加入。
- **剔除出保护区**：保护区面板中可单条移出、多选移出、「全部移出」（需二次确认）；也可在素材列表直接右键移出。
- **保护效果**：

| 场景 | 行为 |
| --- | --- |
| 批量重命名 / 批量移动 / 批量删除 | 受保护项**默认被排除**，并在预览与状态条明确显示「已跳过 N 项（受保护）」 |
| 单条操作 | 允许，但需二次确认，文案显示「该素材受保护」 |
| 强制纳入 | 提供「本次包含受保护项」一次性开关（不解除保护，只对本次生效），勾选时以警示色提示 |
| 提交时校验 | 若受保护项出现在变更集中（先排草稿、后加入保护区的情形），提交前必须显式解除或从变更集移除 |
| 内容去重清理（5.12） | 受保护项默认被排除，同样显示「已跳过 N 项（受保护）」 |

- **【已确认 第 6 条（v1.1）】默认开启所需的配套 UI**（缺一不可）：
  1. **跳过提示**：任何批量操作只要命中受保护项，预览页顶部与底部状态条都必须出现可点击的「**已跳过 N 项（受保护）**」入口，点击后把被跳过项筛选出来逐条查看（名称、路径、加入保护区的时间与方式）。
  2. **本次包含入口**：「**本次包含受保护项**」必须是该提示旁的显式一次按钮（不是藏在设置里的开关），点击后以警示色标记本次计划，并在最终预览与整理报告中留痕（记录「本批次包含受保护项 N 项」）。
  3. **统计口径**：统计 / 概览面板给出「**保护区当周新增 N 项**」（按 `protections.added_at` 落在本周的条目计数），与「保护区总条目数」并列显示，让用户看到保护区的增长速度；当周新增数超标不触发任何自动动作，仅作提示。
  4. **默认开启可解释**：首次触发自动加入时给出一次性说明（「已整理的素材默认加入保护区，批量操作将跳过它们；可在设置中关闭」），避免用户困惑于「为什么批量操作漏掉了一些文件」。
- **保护区不是分组**：分组可被删除、重命名、移动，而保护区是**安全属性**，独立存储于素材标记位，不随分组变动而丢失。
- **保护区的呈现**：带锁徽标 + 专属底色（可在主题中配置）；左侧栏有独立的「保护区」入口，显示条目数；顶部状态条常驻显示「保护区 N 项」。
- **持久化**：跨会话持久化于本地库（应用数据目录）；保护区内容可导出为清单（JSON / CSV）作为备份——注意导出文件**不得写入素材目录**，默认落在用户选择的位置或应用数据目录（第十二节第 1 条）。

### 5.8 预览与报告（F6）

- **预览是强制的**，不可跳过：任何提交前必须经过最终预览页。
- 预览表列：`序号 / 操作类型 / 旧路径 / 新路径（字符级 diff 高亮）/ 体积 / 状态 / 原因`；状态含 正常 / 冲突 / 跳过 / 超长 / 越界 / 受保护 / 目标已存在。
- 预览支持：按状态筛选、按操作类型筛选、逐行勾选取消、导出为 CSV / Markdown 供外部核对。
- **变更集序号与素材序号是两件事**（避免与 5.3.2 的「从 0 开始」混淆）：预览表最左列的「序号」是**行号**（固定从 1 开始，仅用于指认第几行），与文件名中的序号无关；文件名序号按 5.3.2 的起始值与自适应位数设置计算。
- **引用感知提示**（4.3.1）：命中被引用文件的条目，必须在预览中列出引用方（文件 + 行号 + 原文）；「同步改写引用」开启时，另有一张**将被改写的引用行**清单（可逐行取消）。
- 报告（执行后生成）：批次号、时间、各项操作结果、跳过项与原因（含「受保护」跳过项）、失败项与错误、总体统计、是否包含受保护项；**重复内容清理**（重复组 N 组 / 清理 M 项 / 跳过 K 项，5.12）与**改写引用行数**（4.3.1）单列；可导出 Markdown / CSV / JSON。
- **报告不落素材目录**【已确认 第 4 条（v1.1）】：v1.0 中「可选自动保存到工作根下的 `_整理报告/` 目录」**已删除**。报告默认保存到应用数据目录的 `reports/` 下，用户可另存到任意位置；软件**不会**在素材树内自动创建任何报告目录。

### 5.9 冲突、异常与失败策略

| 情形 | 策略 |
| --- | --- |
| 目标名已存在（不同内容） | `suffix`（自动 `_1`、`_2`，默认）/ `skip` / `abort`（整批中止，零变更） |
| 目标名已存在（内容相同） | 视为重复，跳过并记录 |
| 环状改名（A→B、B→A） | **两阶段临时名**处理：先改为批次内唯一临时名，再改为目标名；同时规避大小写不敏感的伪冲突 |
| 被引用文件被改名 / 移动（4.3.1） | 默认仅警告并列出引用方（不阻断、不改写）；开启「同步改写引用」后，改写行随批次进变更集 |
| 文件被占用（Office / 播放器 / 网盘） | 指数退避重试 3 次；仍失败则跳过并写入报告，**不中断整个批次** |
| 路径超长（>260） | 全程使用长路径 API；预览阶段预先标红 |
| 目标盘空间不足 | 提交前预检剩余空间，不足则拒绝提交并给出计算依据 |
| 目标盘不可写 / 只读介质 | 提交前探测，降级为「仅导出计划与报告」 |
| **本地库不可写 / 不存在** | 提交前探测应用数据目录可写性；库不可写时**拒绝一切草稿与提交**并给出修复指引（换库目录或修复权限），**不得**退化为「在素材目录里找个地方写」 |
| 批次中途失败 | 按 journal 状态提供「继续剩余」或「回滚已完成部分」 |

### 5.10 撤销与恢复（F7）

- **journal**：每条变更记录 `批次 / 顺序 / 操作类型 / 源路径 / 目标路径 / 前后状态 / 时间 / 结果`；**journal 只写在应用数据目录**，绝不在素材目录内留下日志文件【已确认 第 4 条（v1.1）】。
- **两处撤销入口**（上下文自动区分，界面必须标明当前是哪种）：
  1. **草稿撤销**（未提交）：不需磁盘操作，瞬间完成，无风险。
  2. **批次回退**（已提交）：按批次或按序号逆序回放逆操作。
- **删除的回退**：依赖回收站，界面必须明示「撤销删除仅在回收站未清空前有效」。
- **内容去重清理的回退**（5.12）：同样依赖回收站，随批次回退恢复。
- **引用改写无独立撤销**（4.3.1）：它随同批次的文件改名一起回退；回退时引用行恢复为原文。
- **崩溃恢复**：启动时扫描状态为 `running` 的批次，提示「上次执行中断，检测到 N 项未完成」，提供继续或回滚。
- **不可撤销情形显式标记**：目标被外部程序改动、回收站已清空、源文件内容在执行后被修改。
- **撤销历史的深度依赖本地库**：库被删除或换机后未迁移，则会话与批次历史一起丢失（代价与对策见 11.4）。

### 5.11 规则方案与复用（F9）

- 规则 = 匹配条件 + 命名模板 + 归档模板 + 冲突策略 + 序号设置，成组保存为「命名方案」。
- 支持：保存、另存为、重命名、删除、设为默认、导入 / 导出 JSON、内置预设方案（相机照片归档 / 设计素材规范 / 下载目录清理 / 工程安全命名）。
- 方案可绑定到特定分组或工作根，也可临时套用到当前选中集。
- **方案的存放**：方案存于本地库（应用数据目录）；「导入 / 导出 JSON」是**用户显式发起**的动作，导出目标由用户选择，软件不会自动把方案文件写进素材目录【已确认 第 4 条（v1.1）】。内置预设随程序分发，不落素材树。

### 5.12 内容去重与重复检测（F10）【已确认 第 4 条，新增】

**条文：内容去重进入 v1 范围（计入 P1）。**判定、清理与留痕都必须可复现、可撤销。

- **判定口径（字节级完全相同）**：先用「**首尾各 64 KB 分段哈希**」（4.4）快速筛选，命中后再比对**文件全长**与整段内容，两者一致才判定为「重复内容」；仅体积相同而哈希不同的一律不算重复。**v1 不做感知哈希 / 相似图判定**（与 4.4「不做颜色 / 内容标签 / 人脸」的边界一致），相似图与视频抽帧比对列为 v2 备选。
- **哈希计算时机**：默认**按需计算**（用户打开「重复内容」集合、或对选中集执行「查找重复内容」时）；设置中可开启「扫描后自动预计算哈希」（默认关闭，见第八节「去重」分组），避免整盘 IO。
- **「重复内容」智能集合**：内置一条智能集合（5.5），规则为「同一内容组内条目数 > 1」，进入即可看到按内容分组的结果；分组、查看与清理动作完全复用 5.5、5.7、5.8 的既有能力，**不新增第二套管线**。
- **保留策略**：每个重复组必须由用户显式选择保留项；默认推荐**保留最早创建的**，可切「保留路径最短」或手工指定。被清理项一律**只进回收站**（5.7），软件内不存在永久删除入口。
- **保护区互动**：受保护项（5.6）默认被排除在清理之外，预览与状态条照常显示「已跳过 N 项（受保护）」。
- **留痕**：整理报告（5.8）必须单列「重复组 N 组、清理 M 项、跳过 K 项（含受保护项）」；撤销走批次回退（5.10），依赖回收站未清空。
- **工作量**：**+2.5 人日**，并入 P1（5.5 → **8.0** 人日）。

**两种子模式**（顶部子分段切换，记忆到配置）：

| 子模式 | 形态 | 适用场景 |
| --- | --- | --- |
| **混排列表（默认）** | 表格：文件夹行分组在前、文件行在后；列 = 名称 ｜ 类型 ｜ 项数 / 大小 ｜ **整理进度** ｜ 修改时间 ｜ 状态 | 整理与批量改名的主场，一屏看清每个文件夹「还剩多少没整」 |

1. **项数**（直接子项文件数；子文件夹另行汇总）；
2. **总大小**（聚合值，取自库）；
3. **整理进度**：`已整理 / 总数` + 细进度条（「已整理」口径见 5.6）；
4. **草稿与待提交计数徽标**（如「草稿 2」「待提交 3」；草稿态用斜体 + 橙色小圆点，与素材三态编码一致，见 5.2）；
5. **保护状态**（含受保护项的文件夹显示锁标；批量操作跳过受保护项并汇总提示，见 5.6）；
6. **被引用状态**（文件夹内有被配置文件引用的素材时显示「被引用」角标，悬停列出引用方与行号，见 4.3.1）。

**交互契约**：

- 单击选中，`Ctrl` / `Shift` 多选（**允许文件夹与文件混选**）；双击进入 = 该文件夹成为主视图根，面包屑同步、前进 / 后退栈入 `nav_history`。
- **展开箭头原地展开一层**：只列出子文件夹与「子项计数摘要」，不做无限层级展开（避免与面包屑导航的语义冲突）【建议】。
- **拖拽**：把文件或文件夹拖到文件夹行 / 卡上 = 移动到该文件夹；目标必须有明确落点高亮与「松开即移动到此处」文案；跨盘移动仍走「复制 → 校验 → 删源」（5.9）；拖拽结果**先进变更集**，不立即写盘。
- 右键菜单：重命名 / 移动到… / 复制路径 / 加入分组 / 加入或移出保护区 / 在资源管理器中打开 / 移入回收站；空白处右键：新建文件夹 / 粘贴 / 全选 / 刷新。

**文件夹自身的增删改一律进变更集**（与素材同等对待）：

- 新建、重命名、移动到别处、删除都先落草稿；界面上以草稿态呈现（斜体名 + 橙色小圆点；新建时名称为可编辑态，默认「新建文件夹」并高亮待命名）。
- 删除文件夹的确认文案**必须写明规模**：「移入回收站（含 22 项）」；文件夹**永不提供永久删除入口**（5.7）。
- 文件夹草稿与其内部文件的草稿在变更集面板中**按文件夹分组折叠**展示，允许整组撤销。

**右栏（选中文件夹时）**：包含项数与类型分布 · 总大小 · 整理进度 · 受保护项数 · 待提交变更列表（按类型分组，可逐条或整组撤销）· 文件夹操作（重命名 / 移动到… / 复制路径 / 在资源管理器中打开）· 整理建议（如「本文件夹有 10 项未按命名规则整理」+ 一键应用到预览）· 危险区（移入回收站，红色样式，写清包含项数）。多选多个文件夹时，右栏切换为**批量操作面板**（重命名规则… / 移动到… / 加入分组 / 加入保护区 / 导出清单），并显示「已选 2 个文件夹（68 项素材）」。

**左栏目录树增强**（与文件夹视图配套）：每行加展开箭头、该目录的待整理数小字、一条 6 px 迷你进度条；树行同样是拖拽目标。

**空与异常状态**：空文件夹显示「空文件夹」+ 拖入提示；无权限、已离线（OneDrive 占位，见 4.2）显示类型化占位与原因，**不得显示为 0 项**；超长路径在名称列中段省略，悬停显示全路径。

**性能约束**：万级场景下与列表视图一致走虚拟滚动；项数、总大小、整理进度均为**库内聚合值**，不得为渲染每行而实时统计磁盘；大规模档（> 20,000，见第八节）默认关闭缩略图拼贴预生成。

**结论：选定 A（Tauri v2）**【已确认 第 2 条（v1.1）】。理由（**v1.1 整段重写**）：

1. **样式生态与令牌化 UI 的匹配度最高，且成本最低、上限最高**。第六、七节要求「一套设计令牌驱动全部外观 + 深度可自定义（主题、强调色、背景图、模糊、密度、深色模式、标记色）」。CSS 自定义属性（变量）天然就是令牌的载体，令牌一改全界面即时生效，无需重建控件树；同时可以直接引入 Tailwind CSS、animate.css 这类**公共第三方样式库**来降低样板量（约束见 10.4）。用 QSS 或 WPF Style/Resource 实现同等效果，工作量与最终上限都更差——这是本轮选型的**首要理由**。
2. **WebView2 系统内建，零安装负担**。Windows 10 / 11 已随系统提供 WebView2 运行时，绿色版解压即用这一核心诉求不需要附带任何浏览器内核；这也是「不装运行时」承诺能够直接落地的关键。
3. **运行时内存占用低、冷启动快**。渲染与 JS 执行发生在系统共享的 WebView2 进程内，而不是为应用再拉起一整套自带浏览器；后台常驻的缩略图与索引任务也不必与一个重框架争内存。第九节的「冷启动 ≤1.5 s」「内存峰值 ≤300 MB」在这条路上最有余量。
4. **无需为跨平台额外投入即可交付**：作者**只做 Windows**【已确认 第 5 条】，因此 Tauri 的跨平台潜力不被计入本期收益，仅为将来可能的变化留出余地，不占用任何本期人日。
5. **UI 与业务逻辑天然分离**，恰好匹配第十一节的分层与「虚拟变更集」这一纯逻辑核心，便于单测与后续换壳。

**v1.0 论证的作废声明（必须明确，避免被旧论据误导）：**

- **作废一：「Tauri 体积最小」**。该论据已被第 1 条批复废止——体积不再设限，体积优势**不再是**选择 Tauri 的理由。A 的体积数据仍保留在表中，但它只作为事实陈述，不参与决策加权。
- **作废二：「Electron 因体积被排除」**。这条旧论据同样作废。**现在排除 Electron 的理由是内存占用与冷启动**：Electron 随包分发完整 Chromium，常驻内存与首屏时间显著高于复用系统 WebView2 的方案，与第九节的「内存峰值 ≤300 MB」「冷启动 ≤1.5 s」冲突。**若将来这两项指标被放宽，Electron 需要作为新候选重新评估，而不是继续引用体积理由排除它。**

**备选方案的保留状态**：B（Python + PySide6）标记为**未采用（备选）**，仅在「一周内用上」的优先级明显高于外观上限、且作者主动推翻第 2 条批复时才重新启用，启用时第七节外观自定义需重新评估工作量（预计 +3 人日，且部分效果达不到）。C（.NET 8 WPF）标记为**未采用（备选）**，仅在作者接受外观自定义打折时考虑。

**架构强制项（不可协商）：**

1. **草稿与磁盘分离**：UI 层的任何写操作只允许调用 `DraftUseCase`；`CommitUseCase` 是**唯一**可以写盘的入口（`立即应用开关` 也走它）。
2. **计划与执行分离**：写盘前必须先生成只读 `Plan`，UI 只渲染与勾选，执行器只接受 `Plan`。
3. **核心域无 IO**：规则、模板、序号、冲突、逆操作必须是纯函数。
4. **一切落盘进 journal**：执行器每完成一条即写日志，崩溃可恢复；journal 写在库目录内，绝不写素材树。
5. **引擎可独立驱动**：提供 CLI（`scan / draft / plan / commit / undo / report / dedupe / backup / restore / migrate`），GUI 出问题时脚本仍可完成工作。
6. **样式令牌单一真源**【已确认 第 2 条（v1.1），新增】：全部颜色、圆角、间距、动效时长只在第七节的设计令牌中定义一次，以 CSS 变量形式暴露；样式框架的主题配置必须映射到同一批变量，组件内**禁止**出现字面色值或独立时长常量。违反此项的补丁不予合入；构建期提供静态检查（见 10.4 第 3 条）。
7. **不在素材树内写入任何自有文件**：所有持久化（库、缓存、日志、报告、方案导出）的默认落点都是库目录或用户显式选择的位置，路径解析集中在 `LibraryUseCase` 一处，禁止散落拼接（第十二节第 1 条）。
8. **引用改写必须与文件改名同批次**【D31，新增】：4.3.1 的「同步改写引用」只能作为同一 `Plan` 的组成部分执行，不得作为独立的写盘路径；关闭该选项时，引用文件**完全不被触碰**。

### 10.3 关键实现要点

- **投影视图**：维护内存中的 `name/path` 投影映射（以 `asset_id` 为键），草稿变更时增量更新；仅在必要时回查数据库。行渲染从投影取值，**不重扫磁盘**。
- **两阶段重命名**：所有改名统一走「先临时名、再目标名」，一并解决环状改名与大小写不敏感伪冲突。
- **缩略图**：优先使用系统缩略图接口（`IShellItemImageFactory`），格式覆盖最广、零额外解码依赖；RAW / HEIC 依赖系统解码器，缺失时降级为类型图标；缩略图缓存写入库目录内的缓存子目录，**不写素材树**。
- **元数据**：图片走内置 EXIF 解析；视频/音频/文档走 Windows Shell 属性系统（4.4）。
- **删除**：`IFileOperation`（`FOF_ALLOWUNDO`）走回收站；不支持回收站时**拒绝删除**，不退化为永久删除。
- **长路径**：全程 `\\?\` 前缀或等价 API。
- **库定位与迁移**：启动时解析库目录（默认 `%LOCALAPPDATA%\鹿铃\`，或便携相对路径 `.\data\`，见第八节「存储」与 11.4），校验可写与是否与任一素材根重叠；重叠时按第十二节第 2 条拒绝或强警告。「库迁移」动作整体搬移库目录并校验条目数，**不触碰素材树**。
- **内容去重**（5.12）：首尾各 64 KB 分段哈希做候选筛选，候选组内再比对全长与内容；哈希结果按 `(size, hash_partial)` 索引缓存，按需计算；判定为止必须能给出「哪几项、依据什么哈希、与谁相同」的可核对证据。
- **引用感知**（4.3.1）：扫描期收集同目录与上溯目录的配置文件文本，抽取文件名（含扩展名）建映射；计划期只做**查表命中**判定，不做递归解析；命中结果参与预览与报告。映射是索引，缺失时退化为不提示。
- **素材树无痕自检**（供验收与自动化测试）：提交前后对素材根做一次目录快照比对，新增条目必须**只**来自用户操作本身（新建文件夹、改名、复制、移动的结果），不得出现任何软件自有文件名模式。

### 10.4 样式与前端依赖策略【已确认 第 2 条（v1.1），新增小节】

作者批复允许引入「诸如 Tailwind CSS、animate.css 等公共第三方样式库」（**原话列举仅作参考，不代表必须使用这两个库**）。本节把「允许」变成有边界的「可以用」。

1. **允许范围**：可以使用通用 CSS 框架（如 Tailwind CSS）、动画库（如 animate.css）、以及与之配套的构建期工具（如 PostCSS）。**它们只是实现手段**：是否使用、使用哪几个，由实现阶段按收益决定；不引入也不违反本节任何要求。
2. **全部本地打包，禁止任何形式的远程加载**（零网络硬约束）：框架与动画库的产物必须随包分发，在构建期编译为本地 CSS / JS 资源。**禁止** CDN 链接、`@import` 远程地址、Google Fonts / 图标字体等网络字体、以及运行时下载样式或字体。首屏字体只能是系统字体或随包字体（6.2）。
3. **设计令牌仍是唯一真源**：
   - 第七节的令牌（CSS 变量）是唯一权威定义；
   - 框架的主题层（如 Tailwind 的 `theme` / `@theme` 配置）必须**映射到同一批变量**，而不是把色值复制一份，也**不得**引入语义重复的第二套变量名；
   - 组件内**禁止写死色值、圆角、间距、时长**；需要新令牌时先在第七节登记，再在全项目中使用；
   - 构建期加一条静态检查（如检索编译产物与源码中的十六进制色值与像素时长字面量），CI 或本地打包脚本中执行，命中即报错。
4. **框架重置样式与既有组件样式的冲突必须收敛**：这类框架会注入一层「重置 / 预置基础样式」（Tailwind 的 preflight 即属此类），它会改变原生表单控件、标题、列表、按钮等的默认表现，与本节第六节既定的组件样式直接冲突（社区常见问题即为此）。处理要求：
   - 优先**关闭该重置层**（Tailwind v3 用 `corePlugins.preflight: false`，v4 用分层导入时跳过 preflight 层 / 把自定义基础样式放进更高优先级的 `@layer base`）；
   - 或者**全部组件样式放进明确的 `@layer`** 中收敛，保证层序固定、可预测；
   - 无论采用哪种，验收时必须逐项核对原生控件（按钮、输入框、复选框、下拉、滚动条、表格）与既有设计规范一致，**不得**因为引入框架而让界面出现「两套观感」。
5. **动画时长必须服从 250 ms 上限**：animate.css 这类库的默认动画时长（通常为 1 s 量级）**违反**第六节「动效 150–250 ms」的规范。补救要求：在全局样式表中用该库提供的时长变量（animate.css 为 `--animate-duration`）统一覆盖到 ≤250 ms，并逐条复核库内**自带固定时长**的动画（覆盖不到的必须禁用或改写）。规范以第六节为准，任何库的默认值都不得"豁免"。
6. **许可证逐版本核对，禁止凭记忆判定**：不得凭印象断定某个库是 MIT 或其他宽松许可证。每个引入的库在其引入版本上必须完成下列动作后才允许进入发布构建：
   - 打开该版本随包自带的 `LICENSE` / `LICENSE.md` / `COPYING` 文件，登记许可证名称与版本号；
   - 确认该许可证允许本项目「私有、禁商业、禁再分发」的分发方式，并与第三节的依赖致谢要求一致；
   - 记入 README「许可与致谢」清单。
   拟引入依赖的核对表（**引入前逐行填写，空行不得发布**）：

   | 依赖 | 用途 | 版本 | 自带 LICENSE 文件 | 许可证 | 是否允许本项目分发 | 核对人 / 日期 |
   | --- | --- | --- | --- | --- | --- | --- |
   | （如 Tailwind CSS） | 原子化样式 | 待定 | `LICENSE`（随包） | **待核对** | **待核对** | 待填 |
   | （如 animate.css） | 动效 | 待定 | `LICENSE`（随包） | **待核对** | **待核对** | 待填 |
   | 其余构建期依赖 | 构建 | 待定 | 随包 | **待核对** | **待核对** | 待填 |

7. **WebView2 运行时的分发口径**（与第 1 条批复的互动，需要作者知晓）：体积不设限意味着绿色版**可以**选择内嵌 WebView2 运行时以保证完全离线可用，代价是安装包增加约 127 MB（离线安装器）或约 180 MB（固定版本运行时）。**【建议】**默认走「使用系统内建 WebView2 + 缺失时提示」的方案（保持绿色版小巧、零网络），仅在企业 / 离线分发场景提供可选的内嵌版构建。此项不作为【待确认】，因为它在体积不设限的前提下只是分发策略，且默认方案已与「零网络」一致。

### 11.2 素材索引与库内的元数据表

```sql
-- 素材索引（磁盘真实状态的缓存）
CREATE TABLE assets (
  id INTEGER PRIMARY KEY,
  volume_id TEXT NOT NULL, rel_path TEXT NOT NULL,   -- 稳定定位键
  name TEXT NOT NULL, ext TEXT, kind TEXT,
  size INTEGER, mtime INTEGER, ctime INTEGER,
  width INTEGER, height INTEGER,
  capture_time INTEGER, camera TEXT,
  hash_partial TEXT,
  missing INTEGER DEFAULT 0,
  UNIQUE(volume_id, rel_path)
);

-- 已整理标记（提交成功后写入，用于「已整理态」与撤销审计）
CREATE TABLE organized (
  asset_id INTEGER PRIMARY KEY,
  first_batch_id TEXT, last_batch_id TEXT,
  organized_at INTEGER, times INTEGER DEFAULT 1
);

-- 保护区（横切安全属性，非分组）
CREATE TABLE protections (
  asset_id INTEGER PRIMARY KEY,
  added_by TEXT,        -- auto / manual
  added_at INTEGER, reason TEXT
);

-- 分组
CREATE TABLE groups (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE,
  kind TEXT NOT NULL,           -- static / smart
  rule_json TEXT, color TEXT, parent_id INTEGER, sort_order INTEGER
);
CREATE TABLE asset_group (
  asset_id INTEGER NOT NULL, group_id INTEGER NOT NULL,
  PRIMARY KEY(asset_id, group_id)
);
```

**设计要点（本节补充）：**

- **内容哈希字段**：`assets.hash_partial` 承载 4.4 / 5.12 的首尾 64 KB 分段哈希；重复内容分组由「同一 `(size, hash_partial)` + 全长比对」在内存中归组，**不额外落一张重复表**（避免第二份真源）。
- **引用映射**【D31】：4.3.1 的「文件名 → 引用它的文件」映射同样存于库内（不落素材树），随扫描增量刷新；表结构在 P3 实现时确定（形如 `refs(ref_name, holder_asset_id, holder_path, line_no)`），**它不是真源**，可随时重建。

### 11.3 草稿、批次日志与配置表

```sql
-- 虚拟变更集（草稿；真实文件未变）
CREATE TABLE drafts (
  id INTEGER PRIMARY KEY,
  seq INTEGER NOT NULL,
  op TEXT NOT NULL,             -- rename / move / copy / mkdir / rmdir / trash / retag / rewrite_ref
  asset_id INTEGER,             -- 新建类操作为 NULL
  src TEXT, dst TEXT,           -- 绝对路径（展示与执行用）
  payload_json TEXT,            -- 附加信息（模板、序号、冲突策略快照）
  check_status TEXT,            -- ok / conflict / illegal / too_long / out_of_root / protected / referenced
  check_reason TEXT,
  created_at INTEGER
);
CREATE INDEX idx_drafts_seq ON drafts(seq);

-- 规则方案
CREATE TABLE rules (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL,
  scope_group_id INTEGER,
  match_json TEXT NOT NULL, rename_template TEXT, target_dir_template TEXT,
  conflict_policy TEXT, seq_json TEXT,   -- 起始值/分隔符/位数(自适应或固定)/作用域（序号位置固定为后缀，不落库、不设置）
  priority INTEGER DEFAULT 0, is_preset INTEGER DEFAULT 0
);

-- 提交批次与操作日志（撤销依据）
CREATE TABLE batches (
  id TEXT PRIMARY KEY, kind TEXT, plan_json TEXT, summary_json TEXT,
  status TEXT,        -- previewing / running / done / partial / undone / interrupted
  started_at INTEGER, finished_at INTEGER, note TEXT
);
CREATE TABLE ops (
  id INTEGER PRIMARY KEY, batch_id TEXT NOT NULL, seq INTEGER NOT NULL,
  op TEXT NOT NULL, src TEXT, dst TEXT,
  before_state TEXT, after_state TEXT,
  status TEXT NOT NULL,   -- done / failed / skipped / undone
  error TEXT, created_at INTEGER
);

-- 设置、阈值、主题
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at INTEGER);
CREATE TABLE themes (
  id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE,
  tokens_json TEXT NOT NULL, is_builtin INTEGER DEFAULT 0, created_at INTEGER
);

-- 浏览历史（前进/后退）
CREATE TABLE nav_history (id INTEGER PRIMARY KEY, path TEXT, visited_at INTEGER);

-- 素材树「不含自有文件」自检快照（10.3 的实现支撑，用于验收与回归）
CREATE TABLE tree_snapshots (
  id INTEGER PRIMARY KEY, root_id INTEGER NOT NULL,
  taken_at INTEGER, entries_json TEXT, note TEXT
);
```

**设计要点：**

- 素材主键不能是绝对路径（盘符变化、改名、移动都会失效）：用 `(volume_id, rel_path)`，`assets.id` 作外部引用键。
- **草稿（drafts）与日志（ops）分开**：drafts 是「将要发生」，ops 是「已经发生」；两者不可混表，否则撤销语义会混乱。
- **保护区用独立表而非分组**：见 5.6，避免保护区随分组删除而丢失。
- `plan_json` 落库，使「中断后继续」「历史计划复查」免费获得。
- **引用改写也是草稿**（`op = rewrite_ref`）【D31】：与文件改名同批次、同一次提交、同一次撤销，不存在旁路写盘（10.2 强制项 8）。
- **全部表在库中，素材树内零落盘**（本节开头总则）；因此「软件外直接读取标签」这一能力**主动放弃**，代之以库的备份 / 导出（11.4 对策二）与可选的清单导出（5.6）。

### 11.4 库成为元数据唯一副本：代价与对策【已确认 第 4 条（v1.1），新增】

把一切元数据集中在库中，换来的是「素材目录绝对干净」，代价是**库同时成为元数据的单点**。必须正面处理三件事，它们都是 v1 的范围，不是可选项：

1. **素材树被移动 / 复制 / 改名后索引失联**（代价）。索引以 `(volume_id, rel_path)` 定位；整个素材树换盘、改目录名、或从一台机器复制到另一台（卷序列号变了）都会让索引全部对不上。
   **对策**：
   - 索引项保留 `volume_id + rel_path` 指纹，并额外记录最后一次已知的 `name`、`size`、`mtime`、`hash_partial` 作为**指纹候选**；
   - 新增「**重新定位素材树**」向导：用户指定新的根目录 → 软件按卷序列号、相对路径后缀、文件名 + 体积 + 时间的多重匹配给出「高置信 / 待确认 / 无法匹配」三档结果 → 用户确认后批量改写 `volume_id` 与 `rel_path`，**分组、标签、保护区、已整理标记、整理历史一律保留**；
   - 无法匹配的条目保留为 `missing` 状态，不自动清理（5.1），也不静默删除任何元数据。
2. **库的备份 / 恢复 / 导出成为必需功能**（代价：这不再是「以后再说」的锦上添花）。重装系统、换机、库文件损坏都会让分组、标签、保护区、整理历史一起消失——因为这些数据在素材目录里**没有任何副本**。
   **对策**（全部进入 v1 范围）：
   - **手动 + 定时备份**：把库（含 journal 与主题设置）导出为单个备份包，默认落在库目录的 `backups/` 下，可另存到任意位置；默认每 7 天提醒一次（第八节「存储」，细项见「十五」），保留最近 N 份、超限滚动删除；
   - **恢复**：从备份包恢复，恢复前必须展示将被覆盖的内容摘要并二次确认；
   - **可读导出**：分组 / 标签 / 保护区 / 素材清单可导出为 JSON / CSV，供人工查看与长期归档（导出去向由用户选择，**不写素材目录**）；
   - **随身迁移**：提供「**把库迁移到指定目录**」的动作（与下一条的第 3 点合并为同一个 `LibraryUseCase.migrate`），供把库放在移动硬盘或网盘同步目录（软件自身不发起任何网络请求，同步由用户的网盘客户端完成）。
3. **库目录位置【已定案，已确认 第 7 条】**：默认 **`%LOCALAPPDATA%\鹿铃\`**，设置中允许改到**程序目录相对路径 `.\data\`**（真正的 Portable 形态，随包搬走即带数据）；两者都**必须**提供「**库迁移**」动作——迁移前展示源 / 目标目录与体积、迁移中给进度、迁移后校验条目数与可写性，并保留旧目录直至用户确认删除。**安装版与绿色版共用同一库目录**（第十二节第 16 条），切换分发形态不得造成库分叉。
4. **库目录不可写时的降级行为**（承接上一条）：默认落点 `%LOCALAPPDATA%\鹿铃\` 不受程序目录只读影响；若作者 / 用户改选相对路径 `.\data\` 而程序目录本身不可写，则**降级到用户目录并在界面上明确提示**「程序目录不可写，库已改到 `<实际路径>`；可在设置中指定固定位置」，同时给出「把库迁移到指定目录」的动作入口。**降级只改变库的落点，绝不退化到「在素材目录里找个地方写」**（第十二节第 13 条、5.9）。

## 十二、安全边界（硬性约束）

1. **素材树零写入**【已确认 第 4 条（v1.1），升级为硬性约束】：除**素材自身与其容器文件夹**外，软件**不得**在素材树内新建、留下或修改任何文件。索引库、journal 操作日志、缩略图缓存、标签、分组、保护区、主题、设置、导出清单、整理报告**全部**存放在应用数据目录（默认 `%LOCALAPPDATA%\鹿铃\`，允许用户改到 `.\data\` 或别处）。
   - **明确禁止**：写 `.tags.json` 之类的侧车文件、在素材目录内建 `.meta/`、`.catalog/`、`_整理报告/` 等自有目录、写说明文件 / 封面图 / 清单文件。
   - **明确禁止依赖系统产生的文件**：不得依赖或读写系统生成的 `Thumbs.db`、`desktop.ini`（它们仍按 4.2 被忽略）。
   - **边界（必须与 5.7 一起理解）**：本约束的准确表述是「**不产生非素材的伴随文件**」，**不是**「素材树只读」。作者明确要求软件内可以新建 / 改名 / 删除 / 移动**文件夹与素材文件本身**（5.7），这些是用户操作的结果，属于正常行为，必须支持。
   - **例外一**：3D / 设计工程包自身的伴随文件与同名依赖目录（`.blend1`、`.fbm/`、`.max_files/` 等，见 4.3）属于**素材本体**，不受本约束限制。
   - **例外二**：4.3.1「同步改写引用」对配置文件（`*.xml` / `*.json` / `*.txt` / `*.js` / `*.css` / `*.html`）的改写，算作**用户显式开启的文件内容修改**，与 5.7 的改名 / 移动同级：默认关闭、进变更集、需二次确认、逐条列出，并同样受「不得留下非素材伴随文件」的约束（它只改既有文件内容，不新建任何文件）。
   - **验收方式**：执行用户操作前后比对素材树快照，新增条目必须全部能归因到用户操作；详见第十六节第 10 条。
2. **库目录与素材树不得重叠**【已确认 第 4 条（v1.1）】：库目录**必须**排除在扫描范围之外（4.2、5.1，不可关闭）。若用户把库目录设置到任一素材根内部，软件应**拒绝**该设置；在无法拒绝的情形（如素材根在设置之后才覆盖到库目录）必须给出**强警告**并要求用户确认或改路径，且扫描与提交前都要复检。
3. **草稿零写盘**：未提交前不得对真实文件系统做任何写操作（缩略图缓存与索引库除外，且必须写在库目录内）。
4. **工作根白名单**：所有写操作目标路径规范化后必须位于已授权工作根内，前缀不匹配一律拒绝。
5. **符号链接与 junction 默认不跟随**；开启时单独确认。
6. **系统与敏感目录拒绝列表**：盘符根、系统目录、`Program Files*`、`AppData`、回收站目录、工作根的父级。
7. **删除只进回收站**；不支持回收站时拒绝删除。
8. **同名冲突永不静默覆盖**。
9. **受保护项默认被排除**于批量操作之外。

## 十六、验收标准（可测）

1. **虚拟变更集**：在软件内执行任意数量的改名/移动/新建/删除后，用系统资源管理器检查，**真实文件与文件夹必须零变化**；关闭时未提交则弹出提醒，且三个选项行为与 5.2 表格一致（含「保存草稿并关闭」后重启恢复草稿）。
2. **崩溃安全**：在草稿态强杀进程，重启后草稿完整恢复，真实文件未被修改；在提交执行中途强杀，重启后能识别中断批次并支持继续或回滚。
3. **序号规则**：**默认起始值为 0 且首个序号为 `0`**（10 项以内的组，自适应补零不补位）；切到起始值 1 时首个序号为 `1`（**0 / 1 双向切换都必须正确**）；序号前自动出现 `_` 且不产生前导或重复下划线；**补零位数符合 5.3.2 的自适应规则（专项验收见第 19 条）**；条目增删后重排正确；起始值 / 位数 / 作用域任一变动时，预览在输入后**立即**给出前三项的最终文件名（自动附加的序号固定位于名称之后，无位置设置项）。
4. **保护区**：受保护项在批量操作中被默认跳过并在预览中列出「已跳过 N 项（受保护）」且可点开逐条查看；「本次包含受保护项」入口有效并在报告留痕；可随时移出并参与操作；跨会话持久；与分组删除互不影响；统计面板的「保护区当周新增数」与实际自动加入记录一致。
5. **文件操作矩阵**：5.7 表中全部操作可用且纳入变更集；`Del` 与 `Shift+Del` 都进入回收站；软件内不存在永久删除入口。
6. **外观自定义**：主题模式、强调色、背景图与不透明度、字体与字号缩放、密度、圆角、三种状态标记色全部生效且即时应用；主题方案可导出并在另一台机器导入后一致；切换主题不丢失选中项与草稿。
7. **样式令牌单一真源**（v1.1 第 2 条批复）：修改第七节任一令牌（如强调色、圆角、动效时长）后，全界面所有相关处同步变化；源码与编译产物中检索不到字面色值 / 硬编码时长；工具类框架的重置样式未改变原生控件表现；第三方动画库的全部动画时长 ≤250 ms。
8. **零网络（含前端资源与更新）**：断网与抓包双重验证，全程无任何外部请求；**不存在任何在线检查更新行为**；构建产物中不存在指向远程域的样式、字体或脚本引用；更新只能由作者手动下载新包覆盖安装。
9. **阈值**：第八节全部阈值可改、生效、夹逼正确；三档规模档位切换行为符合表格描述。
10. **素材树零写入**（v1.1 第 4 条批复）：对任一素材根执行「扫描 → 分组 → 加标签 → 加入保护区 → 批量改名 → 归档 → 提交 → 查看报告 → 导出清单」的完整链路，**提交前后比对素材树快照**，新增条目必须全部可归因到用户操作（新建文件夹、改名、复制、移动的结果），不得出现任何软件自有的文件名模式（如 `.tags.json`、`.meta/`、`_整理报告/`、`Thumbs.db`、`desktop.ini`）；把库目录设置到素材根内部时被拒绝或强警告。

## 十七、结论

本需求在技术层面完全可行，且无未知风险项。v1.2 把 v1.1 遗留的**全部实质待确认项一次收口**：**定名「鹿铃」**（slug `luling`，包标识 `com.yunshumianmian.luling`）让文档、打包、许可证与库目录有了唯一名字；**序号作用域默认「当前文件夹」且原名剥离尾随 `_数字`** 直接对齐作者真实素材（`date_0`…`week_6`、`wz_0`…）的形态；**补零位数改为自适应**（位数 = 组内最大序号值的位数）消除了 v1.1「最小 2 位」在小组内产生 `_00` 的别扭；**内容去重进入 v1**；**安装版与绿色版同时提供**，并把「卸载默认保留库数据、删除须显式勾选、覆盖安装保留库与设置、不做在线检查更新」写成硬约束；**库目录定案**为默认 `%LOCALAPPDATA%\鹿铃\` 并可改到 `.\data\`，配套必需的「库迁移」。（v1.1 曾把「体积不设限」「Tauri v2 + 令牌化外观」「序号从 0 开始」「素材目录零写入」写入口径，这些条文继续有效。）

三个需要额外投入的设计点已经明确并有对策（**v1.2 不变**）：

1. **虚拟变更集**（5.2）——它是作者「操作不立即影响真实文件夹」要求的实现方式，同时也是本项目**最大的安全收益来源**：草稿零写盘，崩溃不损坏素材，撤销草稿不需要动磁盘。它的成本主要在「投影视图 + 实时预检」这一层，约 4.5 人日，值得投入。
2. **保护区**（5.6）——作为横切于分组之上的安全属性，而非分组本身，避免"删了分组保护就丢了"的陷阱；v1.1 确定默认开启后，「不误改已整理素材」成为出厂默认安全姿态，代价是必须把「已跳过 N 项（受保护）」与「本次包含受保护项」的入口做得足够显眼，否则用户会以为是软件漏处理了文件。内容去重的清理动作（5.12）同样受它约束。
3. **库即唯一元数据副本**（11.4，v1.1 新增的最大结构性变化）——它是「素材目录零写入」的必然代价：分组、标签、保护区、整理历史在素材树里**没有任何副本**。因此「库的备份 / 恢复 / 导出」是必需功能，「重新定位素材树」向导与「库迁移」（v1.2 定案）同为必需品。

补充一点（**不改变上面三点**）：**外观自定义（第七节）**仍是第 2 条选型的首要理由（10.1 结论文首条），其投入落在 **P8 的 5.5 人日**内，本节不重复计入；**引用感知（4.3.1，D31）**是本轮唯一仍需作者确认的新增项，其默认行为（只警告、不改写）风险极低，故已按 +1.0 人日计入 P3。
